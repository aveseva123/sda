# Уведомления клиентам салона · интеграция с YCLIENTS

Сервис, который берёт расписание записей и телефоны клиентов из **YCLIENTS** и сам рассылает
напоминания, подтверждения визита, запросы отзывов и приглашения вернуться через
**Telegram → WhatsApp → SMS** с каскадной доставкой: если клиент недоступен в первом канале,
сообщение уходит по следующему. Ответы клиентов («1» — приду, «2» — отменить) возвращаются в
YCLIENTS: запись получает статус «Клиент подтвердил».

Node.js ≥ 22.5, без внешних зависимостей (SQLite встроен в Node). Веб-панель на русском.

## Что умеет

| Функция | Как работает |
|---|---|
| **Расписание и контакты** | Каждые 5 минут опрашивает `GET /api/v1/records/{company_id}` за период «вчера … +14 дней», сохраняет записи, телефоны и имена клиентов локально. Панель показывает расписание по дням с телефонами, мастерами, услугами и статусом каждого уведомления. |
| **Правила рассылки** | Четыре типа: напоминание *до визита* (с кнопками «Подтверждаю / Отменить»), подтверждение *новой записи*, запрос отзыва *после визита* (только если клиент пришёл), приглашение *вернуться* через N дней, если нет новой записи. Фильтры по мастерам, услугам, онлайн-записям. Тихие часы: ночные отправки переносятся на утро. |
| **Шаблоны** | `{{client_name}}`, `{{datetime}}`, `{{services}}`, `{{staff}}`, `{{address}}`, `{{review_link}}` и др.; фильтры `{{client_name\|default:Здравствуйте}}`. Даты форматируются в часовом поясе филиала. |
| **Каскад каналов** | Порядок настраивается (по умолчанию Telegram → WhatsApp → SMS). Переход к следующему каналу при ошибке отправки, при отсутствии подтверждения доставки (WhatsApp) за заданное время или если клиент не подключил канал. |
| **Ответы клиентов** | Кнопки в Telegram/WhatsApp и текстовые ответы («да», «1», «нет», «перенести», «стоп»). Подтверждение ставит `attendance = 2` в YCLIENTS через `PUT /api/v1/record/…`; запрос отмены и свободный текст пересылаются администратору в Telegram. |
| **Внешний API** | `POST /api/v1/messages` — отправить произвольное сообщение по телефону через каскад (для CRM, сайта, 1С). |
| **Панель** | Обзор, расписание, сообщения (исходящие и входящие), правила с предпросмотром, контакты, настройки, журнал. |

## Быстрый старт

```bash
cd notify
cp .env.example .env     # задайте ADMIN_TOKEN, остальное можно настроить в панели
npm start                # http://localhost:8090/
npm test                 # 30 тестов: правила, каскад, клиент YCLIENTS, вебхуки, API
```

Docker:

```bash
docker build -t yclients-notify notify
docker run -d -p 8090:8090 -v notify-data:/data -e ADMIN_TOKEN=secret -e PUBLIC_URL=https://notify.example.ru yclients-notify
```

Для вебхуков Telegram/WhatsApp сервис должен быть доступен по HTTPS (`PUBLIC_URL`). Без `PUBLIC_URL`
Telegram-бот работает через long polling, ничего пробрасывать не нужно.

## Подключение YCLIENTS

1. **Partner token.** Зарегистрируйтесь как разработчик в [маркетплейсе YCLIENTS](https://yclients.ru/appstore/developers)
   и скопируйте API-ключ в разделе «Настройки аккаунта». Без него API YCLIENTS не отвечает.
2. **User token.** В панели (Настройки → YCLIENTS) введите логин и пароль пользователя YCLIENTS с доступом
   к журналу записи; сервис вызовет `POST /api/v1/auth` и сохранит `user_token`. Если у пользователя включена
   двухфакторная авторизация, получите токен вручную и вставьте в поле.
3. **Филиал.** Выберите `company_id` из списка «мои филиалы» или введите вручную.
4. Нажмите «Обновить сейчас» на вкладке «Обзор»: расписание и телефоны появятся во вкладке «Расписание».

Все вызовы идут с заголовками `Accept: application/vnd.yclients.v2+json` и
`Authorization: Bearer <partner_token>, User <user_token>` по [документации YCLIENTS](https://developers.yclients.com/ru/).

Используемые методы: `POST /api/v1/auth`, `GET /api/v1/companies?my=1`, `GET /api/v1/company/{id}/`,
`GET /api/v1/records/{company_id}` (с `with_deleted=1`), `GET|PUT /api/v1/record/{company_id}/{record_id}`,
`GET /api/v1/company/{company_id}/staff/`, `POST /api/v1/company/{company_id}/clients/search`.

Дополнительно есть приёмник `POST /webhooks/yclients?token=…` для событий по записям из маркетплейса
(`{ resource: "record", status: "create|update|delete", data: {…} }`) — он ускоряет реакцию на новые записи,
но не обязателен: опрос API покрывает всё.

## Каналы

**Telegram.** Создайте бота у @BotFather и вставьте токен. Клиент один раз открывает бота, нажимает
«Поделиться номером телефона», и сервис связывает номер с чатом. Ссылку на бота (`t.me/ваш_бот`) удобно
добавить в текст подтверждения записи. Доставка бесплатна. Укажите chat id администратора в «Общие», чтобы
получать запросы на отмену и свободные ответы клиентов.

**WhatsApp.** Используется официальный Cloud API Meta: нужны `Phone number ID` и постоянный access token
приложения, в настройках приложения укажите URL вебхука `…/webhooks/whatsapp` и verify-токен. Вне 24-часового
окна диалога Meta требует утверждённый шаблон: укажите его имя, текст подставляется в параметр `{{1}}`.
Статусы доставки (sent/delivered/read/failed) приходят вебхуком и управляют каскадом.

**SMS.** HTTP-шлюзы `smsc.ru` и `sms.ru` из коробки (логин/пароль или `api_id`, имя отправителя), либо
`custom`: произвольный URL с подстановками `{phone}`, `{text}`, `{sender}` и регулярным выражением
успешного ответа. Опция транслитерации уменьшает стоимость.

**Лог.** Тестовый канал: ничего не отправляет, пишет в журнал. Удобен для отладки правил.

## Внешний API

```bash
curl -X POST https://notify.example.ru/api/v1/messages \
  -H "Authorization: Bearer $API_TOKEN" -H "Content-Type: application/json" \
  -d '{"phone":"+7 916 123-45-67","text":"Ваш заказ готов","channels":["telegram","sms"]}'
```

| Метод | Назначение |
|---|---|
| `POST /api/v1/messages` | `{ phone, text, channels?, buttons?: [{text, action}] }` → сообщение со статусом и каналом |
| `GET /api/v1/messages?status=&phone=&limit=` | список сообщений |
| `GET /api/v1/messages/{id}` | сообщение с попытками по каналам |
| `GET /api/v1/schedule?from=&to=` | записи из YCLIENTS с телефонами (ISO-даты) |
| `GET /api/v1/contacts?q=` | контакты |

Статусы сообщения: `queued` → `sent` → `delivered` → `read`, либо `failed` (все каналы исчерпаны).

## Структура

```
server.mjs              точка входа, загрузка .env
src/config.js           конфигурация из окружения
src/db.js               SQLite: settings, contacts, records, rules, jobs, messages, attempts, inbound, log
src/yclients.js         клиент REST API YCLIENTS, разбор дат, нормализация записей
src/sync.js             загрузка записей в локальный кэш

src/channels/           telegram.js, whatsapp.js, sms.js, log.js
src/inbound.js          разбор ответов клиентов, подтверждение в YCLIENTS
src/app.js              контекст приложения и цикл планировщика
src/api.js, src/http.js HTTP API, вебхуки, статика
public/                 веб-панель
tests/                  node:test (моки YCLIENTS и Telegram)
```

## Ограничения и что дальше

- Для доступа к API YCLIENTS нужен partner token разработчика; тестовый аккаунт можно запросить у YCLIENTS.
- Каналы MAX, VK и Одноклассники не реализованы: у них нет публичного API для сервисных сообщений без
  договора с оператором. Архитектура каналов позволяет добавить их одним файлом в `src/channels/`.
- SMS через SMPP не поддерживается, только HTTP-шлюзы.
- Один экземпляр сервиса обслуживает один филиал YCLIENTS. Для сети салонов запускайте несколько экземпляров
  с разными `DATA_DIR`/`PORT`.
