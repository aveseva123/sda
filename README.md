# Замер деталей — PWA для цеха

Мобильное веб-приложение, которое через камеру телефона измеряет плоские листовые
детали из нержавеющей стали, сверяет их с картой раскроя (DXF) и ведёт реестр
деловых остатков. Работает полностью в браузере, без сервера, офлайн после первой
загрузки.

## Что умеет

| Сценарий | Что делает |
|---|---|
| **A. Приёмка партии** | Детали в один слой + мишень → одно фото → размеры всех деталей, сверка со списком из DXF: найдено / не хватает / лишнее |
| **B. Опознание детали** | Фото одной детали → «Это деталь `SHELF-04` из заказа №1287» |
| **C. Учёт остатка** | Фото обрезка → габарит, полезная площадь, карточка в реестре; позже — «деталь 380×240 помещается в остаток R-019» |

Масштаб задаёт **печатная мишень ArUco** (DICT_4X4_50, id 0–3, метки 40 мм,
центры 130 × 210 мм). Без мишени приложение честно отказывается измерять.

## Быстрый старт

```bash
npm install          # только Playwright для e2e-тестов; в рантайме зависимостей нет
npm run serve        # http://127.0.0.1:8080/  (любой статический хостинг с HTTPS подойдёт для телефона)
npm test             # юнит-тесты и тесты пайплайна на синтетических кадрах (Node 22)
npm run test:e2e     # Playwright: приложение в headless Chromium, тест-режим
```

На телефоне камера доступна только по HTTPS (или на `localhost`). Для цеха
проще всего выложить папку репозитория на любой статический хостинг с HTTPS
и «добавить на главный экран» — дальше приложение работает без сети.

## Мишень

1. Откройте `#/target` в приложении (или файл `target.html`) и распечатайте
   на A4 в масштабе **100 %** (без «подогнать под страницу»).
2. Измерьте контрольный отрезок 100 мм линейкой и введите фактическое значение
   в **Настройки → Мишень**. Приложение учтёт искажение принтера.
3. Мишень лежит **на той же поверхности**, что и детали. Если детали толстые
   (≥ 2 мм) — положите мишень на такой же лист, либо введите толщину и высоту
   съёмки в настройках.

## Правила съёмки

- Мишень и детали — на одной плоскости. Деталь на стопке на 20 мм выше мишени
  измеряется с ошибкой в проценты.
- Детали — в один слой, зазор 2–3 см. Перекрытые кромки алгоритм не видит.
- Основная камера (1×), не сверхширокая. Телефон над столом, наклон до 35°.
- Мишень должна занимать не меньше ~5 % кадра, иначе не хватает разрешения.
- Живые подсказки в видоискателе говорят, что поправить, до снимка.

## Как это работает

1. Фото в полном разрешении камеры (`ImageCapture.takePhoto`, запасные пути —
   `applyConstraints` и системная камера через `<input capture>`).
2. Детекция 4 меток ArUco с субпиксельным уточнением углов → 16 соответствий
   «пиксели ↔ мм».
3. Гомография RANSAC + контроль качества: ошибка репроекции, наклон камеры
   (аналитическое разложение гомографии с самокалибровкой фокуса), доля кадра
   под мишенью, резкость (дисперсия лапласиана), блики.
4. Выпрямление кадра в миллиметровый растр (`warpPerspective`, масштаб из
   наблюдаемого размера метки, не более 4 px/мм).
5. Сегментация: фон = светлый и ненасыщенный (HSV), порог Оцу, морфологическое
   закрытие (заклеивает блики), заливка дыр, фильтр по площади, исключение
   зоны мишени.
6. Замер: `minAreaRect` → субпиксельное уточнение каждой кромки по максимуму
   градиента вдоль нормали → МНК-прямые → углы из пересечений.
7. Сопоставление с раскроем: матрица расхождений с учётом поворота на 90°,
   венгерский алгоритм, порог 3 мм.

Подробный контракт модулей — в [docs/SPEC.md](docs/SPEC.md).

## Чего приложение не делает

- Не определяет марку стали (304 и 316 визуально идентичны).
- Не измеряет толщину листа по фото.
- Не измеряет без мишени в кадре.
- Не использует нейросети — тёмные детали на светлой плите отлично
  сегментируются классическими методами.

## Измеренные показатели (синтетические кадры, Node 22)

| Сценарий | Результат |
|---|---|
| Лист 297 × 210 мм, наклон 0° / 20° / 30°, тени, блик, шум | 297.08 × 210.05 / 297.28 × 210.14 / 297.17 × 210.16 мм |
| Шесть деталей 80…380 мм, наклон 15° | все найдены, ошибка ≤ 0.2 мм |
| Только 2 метки видны (id0, id1), деталь в 300 мм от них | ошибка ≈ 2 мм, предупреждение «видна часть мишени» |
| Кадр 1600 × 1200 | полный цикл ≈ 0.5–0.9 с (в Chromium ≈ 0.9 с) |
| Кадр 12 Мп (4032 × 3024), растр 6 Мп | полный цикл ≈ 1.3 с в Node, ошибка ≤ 0.5 мм |
| Наклон камеры | восстанавливается с точностью 0.1°, фокус — самокалибровкой при наклоне ≥ 15° |

Ошибка репроекции углов ArUco — менее 0.3 px. Субпиксельное уточнение кромок
снимает остаточную ошибку `minAreaRect` (0.05–0.6 мм) практически до нуля.

## Критерии приёмки и тест-режим

Экран **Тест** (`#/test`) позволяет загрузить фото с известными размерами и
получить таблицу «эталон / измерено / ошибка», а также прогнать синтетический
кадр, чтобы убедиться, что пайплайн работает на данном телефоне. Целевые
показатели: 95 % замеров в ±2 мм на деталях 100–1000 мм, сопоставление ≥ 98 %,
цикл «навёл — снял — результат» ≤ 5 с.
