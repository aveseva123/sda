# DECISIONS.md — журнал архитектурных решений

Формат: **что выбрал** / почему / что было альтернативой. Одна строка — одно решение.
Лицензии зависимостей фиксируются здесь же (требование раздела 4 `SPEC.md`).

## M0

- **`cam/` — python-пакет, `tests/` — в корне репозитория, `resources/` — внутри пакета** / стандартная раскладка для pytest и PyInstaller (ресурсы едут в сборку как package data) / `tests/` внутри пакета, как нарисовано в дереве ТЗ.
- **Коды перечислений — ASCII (`ldsp`, `drill_blind`, `in_work`), русские подписи через `.label`** / коды попадают в базу, YAML и имена `.nc`-файлов, где кириллица опасна; интерфейс при этом остаётся русским / хранить русские значения из ТЗ напрямую.
- **Геометрические примитивы — pydantic-модели, дуга задаётся `start/end/center/ccw`** / это ровно форма `G2/G3 I/J`, а контуры без отдельного слоя сериализуются в JSON-колонки / dataclass + ручной (де)сериализатор.
- **Полная окружность — отдельный тип `Circle`, дуга с совпадающими концами запрещена** / у такой дуги нет однозначной длины и направления; присадка — всегда окружность / хранить окружность как дугу на 360°.
- **Допуски в методы геометрии передаются явно, значения — из `resources/defaults.yaml`** / правило «магических чисел в коде нет»; тест увидит, откуда пришёл допуск / константы-умолчания в сигнатурах.
- **Структурные инварианты — в pydantic-валидаторах, инварианты безопасности с порогами (глубина ≤ толщина − 3 мм и т.п.) — в `validate/checks.py` (M3)** / порог «3 мм» — конфиг, а не константа модели; модель не должна знать о профиле станка / всё в моделях.
- **Сквозные операции (`contour_outer`, `contour_inner`, `drill_through`) не имеют поля глубины** / глубина = толщина + запил, считается постпроцессором по профилю станка; хранить её в операции — источник расхождений / хранить и перепроверять.
- **Добавлены поля сверх ТЗ: `TechProfile.verified`, `Operation.low_confidence`, `ImportProfile.units/dims_are/one_file_one_part`, `LayerRule.block_name`** / это прямые требования разделов 8, 9.1, 7.1, 7.3, 7.7, у которых в разделе 6 не было поля / хранить в `extra_params`.
- **Статусы проекта: `new / in_work / done / archived`** / в ТЗ перечень не задан; минимальный набор, уточнить при приёмке / пропустить поле.
- **Время — наивный UTC (`models.utcnow`)** / SQLite не хранит зону; единое представление в базе и моделях, перевод в местное — задача интерфейса / aware-datetime с потерей зоны при чтении.
- **SQLite, WAL, `foreign_keys=ON`, база в локальной папке данных** / раздел 4.1.8: WAL по сети не работает; PostgreSQL — только после ответа на вопрос 24 / SQLite на шаре.
- **Перечисления в ORM — `String`, не `sa.Enum`** / добавление варианта не требует миграции; валидация — на pydantic-слое / `sa.Enum` с CHECK-ограничением.
- **Вложенные структуры (контуры, отступы, параметры, размещения) — JSON-колонки** / они читаются и пишутся целиком, отдельные таблицы дали бы десятки join'ов без пользы для отчётов / нормализация до сегментов.
- **Миграции Alembic запускаются программно (`migrate.upgrade`), env.py требует движок из `attributes`** / `.exe` без консоли обязан сам обновлять базу при запуске; тест сравнивает ORM с миграциями через `compare_metadata` / консольный `alembic upgrade` в инструкции оператора.
- **Резервная копия — через `sqlite3.Connection.backup`, ротация N последних, снимается до миграций** / копирование файла при WAL даёт битую копию; бэкап до миграции позволяет откатить неудачное обновление / `shutil.copy`.
- **Репозиторий — универсальный CRUD `pydantic ↔ ORM` с таблицей агрегатов, обновление через `session.merge` + delete-orphan** / один механизм для 17 сущностей вместо 17 классов; агрегаты (проект → детали → операции) сохраняются одним вызовом / отдельный репозиторий на сущность.
- **Папка данных: `CAM_DATA_DIR` → `%LOCALAPPDATA%\FurnitureCAM` в сборке → `data/` в разработке** / раздел 18: данные отдельно от программы, без прав администратора / рядом с `.exe`.
- **Первичные ключи — целочисленные автоинкременты** / однопользовательская локальная база; UUID усложнил бы стикеры и штрихкоды без выгоды / UUID.
- **Тесты Qt — только `QT_QPA_PLATFORM=offscreen`** / CI и контейнеры без дисплея / xvfb.
- **CI: GitHub Actions, ubuntu + `uv`, `ruff` → `mypy` → `pytest`** / бесплатно, воспроизводит локальный квалити-гейт / без CI.
- **`mypy`: strict на `cam.core`, обычный режим на `cam.ui` и `tests`; overrides для shapely/pyclipper/ezdxf добавляются по мере подключения (ловушка 4.1.7)** / шум частично типизированных библиотек не должен ослаблять проверку ядра / strict везде.
