# DrawingSet — комплект чертежей мебельного изделия из Fusion

Add-in для Autodesk Fusion (Python). По активной 3D-модели, собранной из панелей,
выпускает комплект чертежей и сопутствующие таблицы:

| Модуль | Что делает |
|---|---|
| **А. СБ** — сборочный чертёж | изометрия, главный вид / сверху / слева, габаритные размеры (по флажку — присоединительные), позиционные выноски и спецификация, листы на подсборки |
| **Б. ВЗР** — взрыв-схема | разнесённая изометрия с той же нумерацией; по флажку — схема на каждую подсборку; крепёж скрыт, «едет» с деталью или показан; таблица фурнитуры |
| **В. ДЕТ** — деталировка | лист на каждую уникальную панель (одинаковые объединены с количеством), виды по настройке, авторазмеры, обозначения отверстий, кромка в примечании; для листового металла — развёртка и таблица гибов |
| **Г. Экспорт** | PDF (API), DXF/DWG (через команды UI, см. ниже), CSV-таблицы, отчёт; имя файла по маске `{проект}_{вид}_{изделие}_{тип}`, по флажку — один сводный PDF |

Add-in встраивается после ваших скриптов переименования/нумерации: он **читает** имена
вида `37-4_В1_П03_Боковина` и присвоенные позиции, ничего не переименовывает и своих
номеров не придумывает.

## Что позволяет API Fusion (проверено по справочнику майского релиза 2026)

Это определило архитектуру, поэтому коротко о фактах:

1. **Публичный `adsk.drawing`** содержит только `Drawing`, `DrawingDocument`,
   `DrawingExportManager`, `PDFExportOptions`. Листов, видов, размеров, выносок и
   спецификаций в публичном API нет — создать их «по одному» из Python невозможно.
2. **Скрытый API автосоздания чертежей.** В C++-заголовках того же релиза есть
   `adsk.drawing.DrawingManager` (`createDrawingInput(dataFile, AutomaticDrawingCreationMode)` →
   `createDrawing`) и `AutomationPreferences`: листы главной сборки и подсборок (ISO с
   спецификацией и выносками, ортогональные виды), **листы анимации/взрыв-схемы
   (`GlobalPreferences.isAnimationSheetGenerated`)**, листы деталей с авторазмерами
   (стратегия, база, отверстия), листы развёрток с таблицей гибов, стили видов,
   исключение крепежа по ключевым словам. Все они помечены «hidden and not officially
   supported» и отсутствуют в Python-стабах. Add-in проверяет их наличие **в рантайме**
   (`DrawingSet: Проверка API`) и использует, если они есть.
3. **Анимация.** `Design.animationManager`, `Storyboards.add(isCleanStoryboard)`,
   `Storyboard.activate/playheadPosition` есть. Команд Auto Explode и трансформации
   компонентов в раскадровке в API **нет** (проверено по `Storyboard`/`Storyboards`).
4. **Экспорт.** Из чертежа через API экспортируется только PDF. DXF/DWG листа — только
   командой UI; DXF развёртки листового металла — через `Design.exportManager`.
5. Создание/открытие документов запрещено внутри команды, поэтому конвейер запускается
   из пользовательского события после закрытия диалога настроек.

### Как строится взрыв-схема (по приоритету)

1. **API создания разнесения** — отсутствует, поэтому не используется.
2. **Раскадровка конструктора.** Если в модели есть раскадровка с именем из настроек
   (по умолчанию `[EXPLODE]`, режим `auto`/`storyboard`), add-in активирует её, ставит плейхед
   в конец и создаёт лист через автосоздание с `isAnimationSheetGenerated = True`.
   Предположение: автосоздание берёт активную раскадровку — проверьте на первом изделии.
3. **Разнесённая копия** (запасной путь без ручной подготовки). Add-in сохраняет копию
   дизайна рядом с оригиналом (`<изделие>_EXPLODE`), переводит её в прямое моделирование,
   удаляет соединения и раздвигает вхождения через `Occurrence.transform2`:
   * нормаль панели — ось наименьшего габарита ориентированного бокса;
   * сдвиг вдоль нормали от центра изделия на `max(коэффициент × толщина, шаг мм)`;
   * фасады и задняя стенка отодвигаются сильнее (свои множители), полки выдвигаются
     вперёд; «перёд» определяется по задней стенке, иначе по фасаду, иначе по настройке;
   * центральная перегородка (проходит через центр) остаётся на месте;
   * параллельные панели получают ступенчатый добавок, чтобы не слипались;
   * подсборки едут целиком; по флажку разносятся внутри с меньшим масштабом;
   * крепёж: скрыт / едет с ближайшей панелью / остаётся на месте.
   Копия удаляется после экспорта (флажок «Оставлять разнесённую копию»). Таблица
   смещений всегда пишется в отчёт — по ней удобно подбирать коэффициенты через
   команду «Спецификация» (без чертежей).

### Если скрытого API нет в вашей сборке

Add-in открывает стандартный диалог **Создать чертёж** и показывает, какие листы включить
(режим Automatic). После нажатия OK он сам подхватывает созданный чертёж, добавляет
спецификацию, экспортирует и закрывает его. Такой запуск повторяется для каждого
типа листа (СБ, ВЗР, ДЕТ).

## Установка

1. Скопируйте папку `fusion/DrawingSet` в каталог add-in'ов Fusion
   (Windows: `%APPDATA%\Autodesk\Autodesk Fusion 360\API\AddIns\DrawingSet`,
   macOS: `~/Library/Application Support/Autodesk/Autodesk Fusion 360/API/AddIns/DrawingSet`)
   или укажите путь в **Utilities → Add-Ins → зелёный «+»**.
2. Запустите add-in. В панели **ADD-INS** появятся три команды:
   * **DrawingSet: Проверка API** — сначала выполните её: покажет версию Fusion, наличие
     `DrawingManager`, раскадровок, найденные id команд экспорта DXF/DWG.
   * **DrawingSet: Спецификация** — только анализ: CSV спецификации/фурнитуры/гибов,
     таблица смещений разнесения, отчёт. Ничего в облаке не создаёт.
   * **DrawingSet: Комплект чертежей** — диалог настроек и запуск.

Настройки хранятся в `~/DrawingSet/DrawingSet.settings.json`, логи — в `~/DrawingSet/logs`,
вывод по умолчанию — `~/DrawingSet/out`.

## Структура модели, которую ожидает add-in

Принятые допущения (все настраиваются на вкладке «Модель»):

| Вопрос | Принято |
|---|---|
| Панель — компонент или тело? | Каждая панель — **вхождение компонента с телами**. Компонент без дочерних вхождений и с твёрдыми телами = деталь; с дочерними = подсборка. Одинаковые панели — либо вхождения одного компонента, либо разные компоненты с одинаковыми названием/материалом/толщиной/размером — объединяются с суммой количества. |
| Формат имени | `{проект}_{вид}_{позиция}_{наименование}`, например `37-4_В1_П03_Боковина`. Регулярное выражение с группами `project, view, pos, title` меняется в настройках; суффикс `:1` вхождения игнорируется. Если имя не по шаблону, позиция ищется как отдельный токен, иначе остаётся пустой (предупреждение в лог). |
| Материал | имя физического материала тела (первого твёрдого тела), иначе материала компонента. |
| Толщина и размер | из ориентированного минимального бокса тела: толщина = наименьший габарит, Д×Ш = остальные два по убыванию (мм, округление 0,1). |
| Кромка | атрибут компонента или тела (группа `DrawingSet`, имя `edge`), либо необязательный шаблон в имени с группой `(?P<edge>…)`. Попадает в «Примечание» спецификации и в `description` компонента. |
| Фурнитура | по ключевым словам в названии (конфирмат, петля, направляющ, …) или по геометрии: мелкая (< 120 мм) и не плоская деталь. Скрывается на чертежах через `omitComponentsWithKeywords`, сводится в таблицу фурнитуры. |
| Разрезы / выносные виды | именованные конструктивные плоскости или эскизы с префиксом `РАЗРЕЗ`. API не создаёт виды разрезов, поэтому add-in только перечисляет маркеры в отчёте как ручной шаг. |
| Листовой металл | тело с `isSheetMetal`. Развёртка создаётся по наибольшей плоской грани, если её нет; таблица гибов — из `FlatPattern.getBendInfo` и активного правила листового металла (радиус, K-фактор, толщина). |

Скрытые (выключенная лампочка) вхождения пропускаются.

### Спецификация и номера позиций

Колонки CSV: `Поз.; Наименование; Материал; Толщина; Размер (Д×Ш); Кол-во; Примечание`
(разделитель `;`, десятичная запятая, UTF-8 с BOM — как в остальных скриптах цепочки).

Выноски на автосозданных листах Fusion ставит по **своей** нумерации Item в Parts List.
Чтобы номера совпали с позициями из имён, add-in:

* записывает позицию в `Component.partNumber`, а материал/толщину/размер/кромку —
  в `Component.description` (флажок «Записывать partNumber/description»); эти колонки
  можно включить в Parts List Fusion;
* добавляет свою таблицу спецификации на лист СБ, если доступен скрытый
  `Sheet.customTables`;
* полагается на то, что ваш скрипт перенумерации уже упорядочил компоненты в браузере —
  Fusion нумерует Item в этом порядке.

Совпадение проверьте на первом изделии; если позиции «плавают», расхождение видно
по отчёту (таблица «Спецификация» против Parts List на листе).

## Экспорт

* **PDF** — `DrawingExportManager`, все листы документа. Имя: `{проект}_{вид}_{изделие}_{СБ|ВЗР|ДЕТ|СВОД}.pdf`.
* **Сводный PDF** — отдельный чертёж со всеми типами листов сразу (`…_СВОД.pdf`).
* **DXF/DWG листа** — API нет. Add-in запускает команду экспорта по id из настроек
  (кандидаты подсказывает «Проверка API»; если найден ровно один — берётся автоматически),
  пользователь завершает диалог. Имя файла указывается в отчёте и итоговом сообщении.
* **DXF развёрток** — через `Design.exportManager` автоматически (при включённом DXF).
* **CSV** — спецификация, фурнитура, гибы. **Отчёт** `…_ОТЧЁТ.txt` — возможности API,
  таблицы, смещения разнесения, ручные шаги, предупреждения.

## Проверка без Fusion

Чистые модули (`config`, `naming`, `bom`, `explode`, обход модели с фейковым деревом)
покрыты тестами:

```bash
cd fusion/DrawingSet
python3 -m unittest discover -s tests -t .
```

## Известные ограничения

* Разрезы, выносные виды и ручная правка выносок — вне API; add-in оставляет ручные шаги в отчёте.
* Автосоздание чертежей — скрытый API, он может измениться в следующих релизах; при
  его отсутствии работает полуавтоматический путь через диалог.
* Какую раскадровку берёт автосоздание для листа анимации, документация не уточняет;
  add-in активирует нужную и пишет об этом допущении в лог.
* Разнесённая копия сохраняется в облачный проект и удаляется после экспорта; при
  ошибке посреди запуска копия может остаться — её имя оканчивается на `_EXPLODE`.
