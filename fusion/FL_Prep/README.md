# FL_Prep — add-in Fusion: подготовка модели к чертежам

Шаг «перед чертежами» для корпусной мебели: аудит сборки, нормализация структуры,
свойства для спецификации, очистка видимости, именованные виды, взрыв-схема,
автоматический чертёж и отчёт. Подробная проверка API и план — в `docs/00_API_CHECK.md`.

## Состояние (этап 2)

| Шаг | Состояние |
|---|---|
| 1. Аудит | готов (только чтение) |
| 2–7 | галочки в диалоге есть, но отключены — следующие этапы |
| 8. Отчёт HTML + CSV | готов |
| 9. Экспорт пакета JSON для внешнего генератора чертежей | готов, формат в `docs/01_EXPORT_FORMAT.md` |
| Проба preview/скрытого API | готова, результат печатается в отчёт |
| «Выделить по токену» | готова (отдельная кнопка на панели FL Prep) |

## Установка

1. Скопируйте папку `FL_Prep` целиком в папку add-in Fusion:
   - Windows: `%APPDATA%\Autodesk\Autodesk Fusion 360\API\AddIns\FL_Prep`
   - macOS: `~/Library/Application Support/Autodesk/Autodesk Fusion 360/API/AddIns/FL_Prep`
2. В Fusion: UTILITIES → ADD-INS → Scripts and Add-Ins → вкладка Add-Ins → FL_Prep → Run.
3. На вкладке UTILITIES появится панель **FL Prep** с кнопками «Подготовка к чертежам» и «Выделить по токену».

## Использование

1. Откройте сборку изделия (параметрический режим).
2. UTILITIES → FL Prep → «Подготовка к чертежам». В диалоге: код проекта (определяется из имени
   документа, например «37-4»), галочки шагов, режим dry-run (по умолчанию включён), вкладки
   «Разнесение», «Фильтры», «Вывод».
3. «Выполнить». Прогресс показывается в диалоге, по окончании — сводка и HTML-отчёт
   (`<код>_prep_<дата>.html` + `.csv` в папке отчётов, по умолчанию `~/Documents/FL_Prep_reports`).
   Рядом ложится пакет для генератора чертежей `<код>_export_<дата>.json` (и копия `<код>_export.json`).
4. В отчёте у каждой строки кнопка «токен». Скопируйте его и вставьте в «Выделить по токену» —
   деталь выделится в модели.

Последние настройки диалога сохраняются в `settings.json` рядом с add-in. Там же редактируются
справочник материалов (`materials`), шаблон Part Number и группа атрибутов ваших скриптов.
Лог: `logs/FL_Prep.log` и окно Text Commands.

## Что проверяет аудит (коды в отчёте)

| Код | Уровень | Проверка |
|---|---|---|
| A01_root_body | ошибка | тело лежит в корневом компоненте |
| A02_multi_body | предупр. | компонент с несколькими телами |
| A03_empty_component | инфо | компонент без тел и без вложений |
| A04_no_material / A05_material_unknown | предупр. | нет материала / материал не из справочника |
| A06_body_material_differs | инфо | материал тела отличается от материала компонента |
| A07_default_name / A08_default_body_name | предупр. / инфо | «Component1», «Body3», пустые имена |
| A09_duplicate_name | предупр. | одно имя у разных компонентов |
| A10_geometric_duplicate | предупр. | одинаковая геометрия разными компонентами (объём, площадь, число граней, OBB с допуском 0.01 мм) |
| A11_hidden_component / A12_hidden_body | предупр. | скрытые компоненты и тела |
| A13_pending_position | предупр. | перемещения без Capture Position |
| A14_reference_out_of_date / A15_external_component | ошибка / инфо | внешние ссылки |
| A16_direct_design | предупр. | документ не в параметрическом режиме |
| A00_part | инфо | карточка детали: габарит Д×Ш×Т (мм), число экземпляров, материал |

## Тесты без Fusion

```bash
cd fusion/FL_Prep
python3 -m unittest discover -s tests -t .
```

Чистая геометрия (`lib/geom_pure.py`), отчёт (`lib/report.py`) и сквозной прогон аудита
на заглушке `adsk` (`tests/fake_adsk`) проверяются обычным Python 3.

## Структура

```
FL_Prep.manifest, FL_Prep.py   манифест и точка входа (run/stop)
config.py                      идентификаторы UI, группа атрибутов, значения по умолчанию
commands/prep/entry.py         диалог и execute основной команды
commands/select_by_token/      команда «Выделить по токену»
lib/capabilities.py            проба preview/скрытого API (hasattr + try/except)
lib/traversal.py               обход occurrences, один компонент — один раз
lib/geom_pure.py               чистая геометрия: OBB, дубли, имена, код проекта (без adsk)
lib/audit.py                   шаг 1
lib/exporter.py                шаг 9: пакет JSON (контуры панелей, отверстия, сетки, дерево сборки)
lib/pack_pure.py               чистые функции формата экспорта (без adsk)
lib/report.py                  шаг 8: HTML + CSV
lib/pipeline.py                оркестрация шагов
lib/settings.py, lib/log.py    settings.json, лог в файл и Text Commands
tests/                         unittest + заглушка adsk
docs/00_API_CHECK.md           проверка API и план
docs/01_EXPORT_FORMAT.md       формат пакета экспорта
```

## Известные ограничения этапа 2

- Все изменения модели идут внутри `execute` команды (один Ctrl+Z); в этапе 2 модель не меняется.
- Габариты через `orientedMinimumBoundingBox` (Fusion ≥ январь 2024); на старых сборках —
  запасной расчёт по нормали самой большой плоской грани и вершинам тела.
- Признак «позиция не зафиксирована» доступен только для всего дизайна, не по компоненту.
- Add-in не запускался в реальном Fusion из этой среды: первый прогон на рабочей сборке —
  за вами, лог и сообщения об ошибках выводятся в `logs/FL_Prep.log` и messageBox.
