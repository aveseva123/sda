# Формат пакета экспорта `fl_prep_export` (версия 1)

Один JSON на изделие. Все длины в **мм**, углы не используются, матрицы 4×4 row-major
(16 чисел, перенос в элементах 3, 7, 11). Файл пишется дважды: `<код>_export_<дата>.json`
и `<код>_export.json` (последний прогон) в папке отчётов.

```json
{
  "format": "fl_prep_export", "version": 1, "units": "mm",
  "exported_at": "2026-09-15T18:20:00", "exporter": "FL_Prep",
  "project_code": "37-4",
  "document": {"name": "Бар 37-4 стойка", "version": 12, "is_saved": true},
  "root": {"name": "Бар 37-4 стойка v12", "token": "...", "bodies": []},
  "settings": {"part_number_template": "...", "helper_prefixes": [], "hardware_prefixes": [], "materials": []},
  "components": [ ... ],
  "occurrences": [ ... ]
}
```

## components — уникальные компоненты (каждый один раз)

| Поле | Значение |
|---|---|
| `id` | entityToken компонента (стабильный ключ, им же ссылаются occurrences) |
| `name`, `part_number`, `description`, `material` | как в Fusion |
| `material_ref` | имя записи справочника (`ЛДСП`, `МДФ`…) или `null` |
| `kind` | `part` (деталь с телами), `assembly` (есть вложенные компоненты), `hardware` (по префиксу или материалу), `helper` (по префиксу; в пакет попадает только по настройке), `empty` |
| `instances` | число вхождений в изделии (для спецификации) |
| `attributes` | `{"FL_PREP": {...}, "<группа ваших скриптов>": {...}}` |
| `obb` | `{length, width, thickness, source}` — габарит Д ≥ Ш ≥ Т; `source`: `api` (Fusion orientedMinimumBoundingBox), `faces` (по нормали главной грани), `aabb` |
| `frame` | система координат детали в локальных координатах компонента: `origin` (центр OBB), единичные `x` (длина = ось текстуры), `y` (ширина), `z` (наружная нормаль главной грани). Правая тройка |
| `grain_axis` | `"x"` — текстура вдоль длины |
| `panel` | `null`, если деталь не панель (толщина > 60 мм, толще половины ширины или главная грань меньше половины габарита) |
| `mesh` | `{vertices: [x,y,z,...], triangles: [i,j,k,...]}` в **локальных координатах компонента** (не в frame) |

### panel

```json
"panel": {
  "main_face_body": "Полка", "main_face_area": 240000.0,
  "outline": {"outer": [[segment, ...]], "inner": [[segment, ...], ...]},
  "drillings": [
    {"center": [-300, 100, 8], "diameter": 8, "axis": [0, 0, -1], "face": "main", "through": true, "body": "Полка"}
  ]
}
```

- Контур задан в 2D-координатах `(u, v)` системы `frame` (u вдоль `x`, v вдоль `y`), взгляд на главную
  грань снаружи (по −z). Петли идут в порядке обхода Fusion; `outer` обычно одна, `inner` — окна, пазы, вырезы.
- Сегмент: `{"type": "line", "points": [[u,v],[u,v]]}` · `{"type": "arc", "center": [u,v], "radius": r, "ccw": true, "points": [...]}` ·
  `{"type": "circle", ...}` · `{"type": "polyline", "points": [...]}` (сплайны и прочее, дискретизация с допуском сетки).
- `drillings` — круглые внутренние петли на всех плоских гранях всех тел. `center` — 3D в системе `frame`
  (третья координата: +T/2 главная грань, −T/2 обратная, торцы между). `axis` — направление сверления
  внутрь материала, в системе `frame`. `face`: `main` / `back` / `edge`. Сквозные отверстия (видны с обеих
  плоскостей) объединены в одну запись с `through: true`. Глубина глухих отверстий пока не экспортируется.

## occurrences — вхождения (экземпляры) в дереве сборки

| Поле | Значение |
|---|---|
| `id` | entityToken вхождения |
| `name`, `path` | `Полка:2`, `Тумба:1+Полка:2` |
| `parent` | `id` родительского вхождения или `null` для первого уровня |
| `component` | `id` компонента |
| `depth` | уровень вложенности (0 — первый уровень) |
| `transform` | матрица положения компонента **относительно корня** (`transform_space: "root"`), мм |
| `visible`, `grounded` | видимость (лампочка) и фиксация |

Скрытые вхождения не экспортируются, если не включена настройка «включать скрытые».

## Как генератор получает мировые координаты

`world = transform(occurrence) · local`, где `local` — точка сетки компонента; точка контура панели
переводится из `(u, v, w)` в локальные: `local = frame.origin + u·frame.x + v·frame.y + w·frame.z`.
